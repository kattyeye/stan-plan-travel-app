## What Is This

Stan Plan is a travel planning SaaS. The customer fills out a short wizard about their trip, pays via Stripe, and receives a personalized trip plan generated by Claude AI — including a day-by-day itinerary, meal plan with recipes, grocery list, restaurant guide, activity tips, and packing list.

Each customer gets:
1. A live web app at `/trip/[slug]` they can share with their travel group
2. A self-contained downloadable `.html` file they can print or save as PDF

The key differentiator is the **planning style axis** — a "structured" family gets a minute-by-minute schedule, a "flexible" group gets loose suggestions. Same destination, completely different feeling document.

## Design System

### Philosophy
- Warm, organic, earthy — feels like a trusted friend planned your trip
- NOT generic SaaS — no purple gradients, no Inter font, no cookie-cutter components
- All styling via CSS custom properties — **do not hardcode hex values, always use tokens**

- **Headings/display:** Instrument Serif (`font-display` class) — editorial, warm

## Data Flow

```
User fills wizard
      ↓
POST /api/stripe/checkout → Stripe Checkout URL
      ↓
User pays on Stripe
      ↓
Stripe webhook → POST /api/stripe/webhook → marks trip "paid"
      ↓
Frontend polls → triggers POST /api/generate
      ↓
/api/generate:
  1. Verify Stripe session
  2. Generate slug (lib/slug.ts)
  3. Save trip record to MySQL (status: "generating")
  4. Build system prompt + user prompt from wizard data
  5. Call Claude API → returns GeneratedTrip JSON
  6. Call Claude API again → returns self-contained HTML string
  7. Save generatedData + HTML to MySQL (status: "ready")
  8. Email customer their trip link
  9. Return { slug }
      ↓
Redirect to /trip/[slug]
      ↓
Page fetches trip from MySQL, renders React components
```

## Claude Prompts

Three prompt files in `src/prompts/`:

**system.txt** — Role definition, quality rules, planning style behavior:
- `structured`: exact times (9:00am — Kayak rental at X), assigned restaurants per meal
- `balanced`: morning/afternoon/evening buckets, primary + one alternative
- `flexible`: themes/moods per day, 2-3 options per meal, suggestion language

**json-schema.txt** — Instructions to return valid JSON only matching GeneratedTrip type. Key rules:
- `recipes[]` is the single source of truth — both itinerary and groceryList reference by `recipeId`
- Scale all ingredient amounts to exact group size
- Use web search to verify all restaurant names + hours before including

**html-template.txt** — Takes GeneratedTrip JSON, renders self-contained HTML with 5 tabs, working checkboxes, expandable recipe cards, print stylesheet, offline-capable.

## Key Rules When Working on This Project

1. **Never hardcode colors** — always use CSS custom properties (`var(--brand)` not `#778745`)
2. **Never modify files in `src/components/ui/`** — that's the Tailwind UI kit, leave it alone
3. **Always add `"use client"` to any component that uses useState, useEffect, or event handlers**
4. **`recipes[]` is the source of truth** — itinerary and grocery both reference by `recipeId`, never duplicate recipe data
5. **Run `npm run build` after every significant change** — catch TypeScript errors before pushing
6. **The planning style must affect output everywhere** — itinerary format, copy tone, restaurant assignment, activity suggestions all vary by `structured | balanced | flexible`
7. **Commit messages:** `feat:`, `fix:`, `style:`, `deps:`, `refactor:` prefixes

## Common Issues & Fixes

**White screen on /wizard**
Usually a missing `"use client"` directive or a component trying to use browser APIs during SSR.
Check the browser console for the actual error.

**Build fails with "Cannot find module"**
Run `npm install [package-name]` — a dependency is missing from package.json.

**CSS tokens not applying**
Make sure globals.css is imported in layout.tsx and the token name is spelled exactly right.
Tokens only work in inline styles as `style={{ color: 'var(--text-primary)' }}` or in CSS files.
They do NOT work directly in Tailwind utility classes.

**Claude API returns malformed JSON**
The system prompt must end with: "Return valid JSON only. No markdown fences. No preamble."
Parse with try/catch and log the raw response if it fails.

## Context From Planning Sessions

This project was planned in detail across multiple Claude.ai conversations. Key decisions made:

- **Two Claude API calls per trip:** first for JSON (structured data), second for HTML (rendered file)
- **JSON is source of truth:** HTML is generated from JSON, not independently
- **Recipe deduplication** happens in frontend (`src/lib/utils.ts`), not in Claude's output
- **Planning style is injected into both the system prompt and the UI rendering** — the output should *feel* different, not just have different content
- **No auth for MVP** — trips are accessed by slug URL only, no login required
- **Stripe payment gates generation** — trip record is created before payment, generation only triggers after webhook confirms payment
