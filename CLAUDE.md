## What Is This

Irie is a travel planning SaaS. The customer fills out a short wizard (or speaks
their trip), pays via Stripe, and receives a personalized plan generated by
Claude — day-by-day itinerary, meal plan with recipes, grocery list, restaurant
guide, activity tips, and packing list.

Each customer gets:
1. A live web app at `/trip/[slug]` they can share with their travel group
2. A self-contained downloadable `.html` file they can print or save as PDF

The key differentiator is the **planning style axis** — a "structured" family
gets a timed schedule, a "flexible" group gets loose suggestions. Same
destination, completely different feeling document.

- **Framework:** Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS v4

## Design System

### Philosophy
Warm, organic, earthy — like a trusted friend planned your trip. Not generic
SaaS: no purple gradients, no cookie-cutter components.

### How styling works here — read this before touching a component
The app styles almost entirely through **inline `style={{}}` objects** whose
values are `var(--color-*)` CSS custom properties. Tailwind utility classes are
barely used in shipped code. This is deliberate: inline style objects map
cleanly onto React Native `StyleSheet` for the planned mobile app.

Token flow:
```
src/theme/palette.ts  ─┐
                       ├─→ npm run tokens ─→ src/app/tokens.generated.css ─→ var(--color-*)
src/theme/tokens.ts   ─┘                └─→ (future) React Native theme object
```

**Rules:**
1. **Never hardcode a hex value** outside `src/theme/palette.ts`.
2. **Never edit `tokens.generated.css`** — edit `tokens.ts` and run `npm run tokens`.
3. **Use semantic tokens, not raw ramps.** `var(--color-bg-card)`, not
   `var(--color-tea-green-100)`. Raw ramp values are light-mode-specific and
   break dark mode — that was a real bug class here.
4. `npm run tokens` runs automatically via `predev` / `prebuild`.

### Fonts
- Headings/display: **DM Serif Display** → `var(--font-display)`
- UI/body: **Inter** → `var(--font-sans)`

Both are loaded by `next/font/google` in `layout.tsx`, bound to those variable
names. Do not add a third font.

### Dark mode
`next-themes` puts a `.dark` class on `<html>`. Every semantic token has a dark
value. Because components read tokens through the cascade, they adapt for free —
*provided they use semantic tokens*.

## Data Flow

```
Wizard (or voice intake)
      ↓
POST /api/stripe/checkout  → creates trip record (status "pending") → Stripe URL
      ↓
User pays
      ↓
Stripe webhook → marks "paid" → triggers generation
      ↓
/trip/[slug]/generating polls /api/trip until status is "ready"
      ↓
Generation: wizard data → Claude (JSON) → Claude (HTML) → Redis → status "ready"
      ↓
/trip/[slug] renders the React trip view
```

Generation runs **synchronously** inside the request (`maxDuration = 300`),
because Vercel kills the process once a response returns — fire-and-forget does
not work. The client polls rather than waiting on that request.

**Always start generation via `runGeneration()` in `src/lib/generate.ts`.** It
takes a Redis `SET NX` lock, which is what stops the webhook and the generating
page from both firing a run for the same trip (that bug cost two Claude
generations per purchase).

**Stored trips are normalized on read.** `normalizeTrip()` upgrades older trips
whose activities are prose strings ("9:00am — Kayak rental") into structured
objects with real times. Call it at the read boundary; never render a raw
`GeneratedTrip`.

### Redis keys
| Key | Value |
| --- | --- |
| `trip:<slug>` | the full `TripRecord` |
| `session:<stripeSessionId>` | slug, so the webhook can find the trip |
| `suggest:<destination-slug>` | cached suggestions, 7-day TTL |

## Key Rules

1. **Never hardcode colors** — semantic tokens only (see Design System above).
2. **Add `"use client"`** to any component using `useState`, `useEffect`, or
   event handlers. Trip sections that are purely presentational stay server
   components deliberately — don't add the directive without needing it.
3. **`recipes[]` is the source of truth** — reference by `recipeId`.
4. **Run `npm test` and `npm run build` after every significant change.**
   `npm test` covers the pure logic in `src/core`; the build catches
   everything else. Lint currently has zero errors — keep it that way.
5. **Keep `src/core/` platform-free.** No React, no `next/*`, no DOM, no
   `localStorage`, and no importing from `src/lib` or `src/components`. A test
   enforces this, because a React Native app imports that directory wholesale.
   Web- or server-specific code belongs in `src/lib`.
6. **Planning style must affect output everywhere** — itinerary format, copy
   tone, restaurant assignment, activity suggestions.
7. **Generation costs real money.** Each trip is two Claude calls. When testing,
   reuse existing slugs via `/admin/trips` regenerate rather than running the
   full wizard repeatedly.
8. **Commit prefixes:** `feat:`, `fix:`, `style:`, `deps:`, `refactor:`, `docs:`

## Common Issues & Fixes

**White screen on a page**
Usually a missing `"use client"` or a browser API used during SSR. Check the
browser console for the real error.

**A component looks fine in light mode and unreadable in dark**
It is using a raw ramp token (`--color-tea-green-200`) or a literal `#ffffff`
instead of a semantic token. Swap to `--color-bg-card` / `--color-text` etc.

**CSS tokens not applying**
Tokens work in inline styles as `style={{ color: 'var(--color-text)' }}` and in
CSS files. They do **not** work as bare Tailwind utility class names.

**Claude returns malformed JSON**
The prompt must end with "Return valid JSON only. No markdown fences. No
preamble." Parsing already strips fences defensively and logs the raw response
on failure — check the server logs.

**Trip stuck on the generating screen**
Check the record in Redis: status `error` means generation threw (see logs),
status `generating` that never advances usually means the function timed out.
